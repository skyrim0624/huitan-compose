# 灰谈制作 Skill

`huitan-compose` 是一个用于制作大灰「灰谈」系列的 Codex Skill。它帮助把一次真实咨询、访谈、聊天转写或提问者背景材料，整理成可以公开发布的中文公共案例文章、对谈稿和编辑工作包。

这个 Skill 的重点不是把录音转写成摘要，而是完成一次「个案公共化」：从一个人的具体困境出发，看见背后的公共议题，再写成更多读者能代入、反思、复用的栏目文章。

## 适用场景

- 大灰咨询、灰谈录音、访谈转写、聊天记录整理成文章。
- 从提问者原始问题和背景中提炼公共议题。
- 生成个案卡、文章角度、调研清单、引用库、结构大纲、初稿和编辑审查。
- 制作公众号长文、对谈稿、发布正文、小红书或社群帖的素材包。
- 维护灰谈系列稳定的文风、伦理边界和排版规则。

## 核心原则

- 先做编辑判断，再写文章。
- 把大灰写成「重构问题的人」，而不是给标准答案的权威导师。
- 把提问者写成真实的人，不写成案例工具人或反面教材。
- 只引用材料里真实出现的内容；不确定的原话改为转述并标记待确认。
- 公共化不是拔高，每个宏观判断都要回到人物、场景、选择和代价。
- 默认处理隐私、未授权细节和商业敏感信息，必要时标记发布前确认。

## 安装

把仓库放到 Codex 的 skills 目录下：

```bash
git clone https://github.com/skyrim0624/huitan-compose.git ~/.codex/skills/huitan-compose
```

如果本地已经存在这个目录，可以直接更新：

```bash
cd ~/.codex/skills/huitan-compose
git pull
```

## 使用方式

在 Codex 对话里调用：

```text
$huitan-compose
```

可以直接给材料并说明目标，例如：

```text
$huitan-compose
请把这段大灰咨询转写整理成一篇灰谈公众号稿。材料包括提问者背景、正式转写和公开边界。
```

如果没有指定单一交付物，Skill 默认按这个顺序产出：

1. `case-card`：个案卡
2. `angle-options`：文章角度选项
3. `research-brief`：调研与核查清单
4. `outline`：文章结构
5. `draft`：初稿
6. `editor-review`：编辑审查

如果用户明确要求「对谈稿、访谈稿、发布正文、公众号稿」，优先输出 `dialogue-draft` 成稿，再附必要的编辑审查。

## 建议输入

材料不完整时也可以开始，但最好尽量提供：

- 提问者原始问题。
- 提问者背景：职业、项目、阶段、压力、已经尝试过的做法。
- 正式对话转写：含说话人和时间戳更好。
- 上下文材料：项目介绍、历史文章、社群背景、行业资料。
- 公开边界：是否实名，哪些细节不能写，哪些判断需要确认。
- 目标平台：公众号、长微博、小红书、社群帖或播客 shownotes。

## 排版硬规则

访谈整理稿的小标题必须放在本节核心问题之前，形成「小标题 -> 提问者追问 -> 大灰回应」的阅读顺序：

```md
## 2. 社区最值钱的，不是房费

*子扬：* 这个点我能感觉到。我们之前其实也想过不能只靠住宿，但没有定得很清楚。

*大灰：* 社区本身最珍贵的东西，不是房费。
```

不要把小标题夹在提问者追问和大灰回答中间。那会让标题变成回答摘要，而不是开启一个完整小节。

## 边界

- 不编造转写里没有出现的事实、原话或经历。
- 不替代发布授权、事实核查和隐私确认。
- 不把高隐私密度材料直接公开；职业、家庭、收入、健康相关细节默认需要脱敏或确认。
- 不把文章写成会议纪要、大灰观点整理、营销号爆款文或鸡汤结尾。

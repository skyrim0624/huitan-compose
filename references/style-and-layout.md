# 文风、口吻与排版

## 总体气质

目标是“有现场感的公共案例文章”。借鉴青年志、十字路口 Crossing 等栏目时，取其编辑意识，不模仿具体句式。

采用：

- 温和但有判断
- 具体但不琐碎
- 有分析但不论文腔
- 有故事但不煽情
- 有方法论但不培训课

避免：

- “本期大灰指出”“本文总结了三点”这类会议纪要腔
- “底层逻辑、认知升级、破局、闭环、赋能”等油腻词堆砌
- 连续排比和过多“不是……而是……”
- 把个人故事写成宏大时代寓言
- 为了金句牺牲准确性

## 叙述口吻

默认第三人称或近距离第三人称。可以偶尔使用“我们”，但不要替读者下结论。

好的口吻：

- “他原本以为自己在问一个运营问题。”
- “聊到这里，问题开始变形。”
- “大灰没有急着给方案，而是先把服务对象重新摆到桌面上。”

不好的口吻：

- “这给了所有人一个深刻启示。”
- “大灰一针见血地指出了底层逻辑。”
- “只要做到以下几点，就能完成商业化。”

## 开头方式

优先从具体场景进入：

- 一句话困境
- 一个对话片段
- 一个反常识事实
- 一个提问者原本没有意识到的矛盾

不要从栏目介绍、背景大段科普、抽象概念开始。

## 标题方向

标题要指向“个案中的公共问题”，不是只写人物或主题。

可用结构：

- “他来问 X，最后发现真正的问题是 Y”
- “一个社区开始商业化时，最先要放下什么”
- “大灰和他聊了 40 分钟，真正被改写的是用户是谁”

避免：

- “灰谈第一期：关于社区商业化的深度思考”
- “大灰给 CMI 的十条建议”
- “如何打造一个成功社区”

## 正文排版

适合公众号和长文平台：

- 段落短，通常 1-4 行。
- 小标题克制，服务结构，不制造鸡血。
- 访谈整理稿的小标题必须放在本节核心问题之前：先用小标题框定这一节要解决的问题，再放提问者追问，最后接大灰回答。
- 不要把小标题夹在“提问者问题”和“大灰回答”之间；那会让标题看起来只是在概括回答，而不是开启一个完整小节。
- 每 800-1200 字出现一次结构转折。
- 原话引用少而准；长转写改为转述。
- 可用加粗突出关键判断，但不要整段加粗。
- 保留 2-4 个可做海报或小红书切片的句子。

## 对谈稿整理

- 对谈稿不是逐字稿压缩，而是一次“问题被改写”的阅读重建。
- 先归一说话人标签；如果转写工具把提问者识别成符号或乱码，从文件名、结尾称呼和上下文推断。
- 保留真实问答关系，但可以把零散追问整理成更清楚的一问，前提是不新增事实。
- 大灰长段输出较多时，用小标题、短段落和整理型追问恢复对话节奏，避免变成单人讲课。
- 职业、家庭、收入、健康相关细节默认高隐私密度；成稿中可脱敏，编辑审查中列为发布前确认项。

### 访谈小标题位置

正确顺序：

```md
## 2. 社区最值钱的，不是房费

*子扬：* 这个点我能感觉到。我们之前其实也想过不能只靠住宿，但没有定得很清楚。

*大灰：* 社区本身最珍贵的东西，不是房费。
```

错误顺序：

```md
*子扬：* 这个点我能感觉到。我们之前其实也想过不能只靠住宿，但没有定得很清楚。

## 2. 社区最值钱的，不是房费

*大灰：* 社区本身最珍贵的东西，不是房费。
```

判断方法：如果一个小标题概括的是接下来一轮问答的议题，就必须出现在这轮问答之前；除非它明确只是对上一段的总结，否则不要放在问题之后。

## 文章节奏

推荐节奏：

1. 先让读者看见人。
2. 再让读者看见问题。
3. 再让读者发现问题被问错了。
4. 再展开大灰如何重构。
5. 再把这个个案推向公共议题。
6. 最后回到行动和代价。

## 灰谈栏目识别

每篇都要形成一个隐性栏目感：

- 有一个真实问题作为入口。
- 有一轮问题重构作为核心事件。
- 有一个可公共讨论的命题作为文章骨架。
- 有一个不完美但可行动的现实结尾。

栏目不要显得像咨询服务广告。文章价值应来自案例本身，而不是反复证明大灰厉害。
